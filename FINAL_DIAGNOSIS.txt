FINAL ROOT CAUSE:
-----------------
✗ MobileNetV3 + ONNX Runtime static PTQ = ARCHITECTURALLY INCOMPATIBLE

Why:
- Hardswish decomposition: x * hardsigmoid(x) → separate Conv, HardSigmoid, Mul ops
- Static PTQ assigns different scales to each op
- Scale mismatch between HardSigmoid output and Mul input → broken semantics
- Error propagates through entire network
- Result: random predictions (correlation=0.39, should be >0.95)

Tried fixes (ALL FAILED):
- ✗ QUInt8 activations (correct type, still broken)
- ✗ Increased calibration 200→500→1000 samples (no improvement)
- ✗ Opset 13→14 (no change)
- ✗ Dynamic quantization (ConvInteger op not supported in ORT 1.15)

CONCLUSION:
-----------
This is a KNOWN LIMITATION of ONNX Runtime static PTQ.
Models with Hardswish/Swish cannot be quantized with static PTQ.

WORKAROUNDS:
------------
1. Use Quantization-Aware Training (QAT) instead of PTQ
2. Use FP16 instead of INT8 (2× compression, lossless)
3. Use different teacher (ResNet50, EfficientNetV2-M work fine)
4. Keep MobileNetV3 as FP32-only baseline
